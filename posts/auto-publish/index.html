整條線長這樣

素材進去，兩個平台出來

中間那顆圖床是多數人卡住的地方。兩個平台的 API 都只接受公開網址，不能上傳本機檔案，所以圖片必須先有個家。

SETUP

四個步驟，一次設定完

Threads 很快就好。Instagram 是整趟裡最花時間的一段，關卡多，而且順序錯了要重來。

  1. 01

    拿 Threads 的鑰匙約 5 分鐘

    到 Meta 開發者後台建一個 App，加上 Threads 的用途，產生 access token。

    效期 60 天，到期前刷新一次就好，不用重新申請。

  2. 02

    架一個圖床約 10 分鐘

    開一個 public 的 GitHub repo 當圖床，再產一把 fine-grained token，權限只要勾 Contents: Read and write。

    為什麼需要這個：Threads 和 IG 的 API 都只吃公開網址。你桌面上的圖，API 根本看不到。這是整趟最容易漏掉的一步，因為文件不會提醒你。

  3. 03

    拿 Instagram 的鑰匙約 40 分鐘

    四道關卡缺一不可，而且必須照順序：

    ① IG 轉專業帳號並連結 Facebook 粉專
    ② Meta App 加入 Instagram 用途，選「Instagram business login」這條路，不要選需要送審的那條
    ③ 先補上發文權限 instagram_business_content_publish
    ④ 把自己的 IG 加成 Instagram Tester，然後去 instagram.com 接受邀請

  4. 04

    給 Agent 一份說明書一次寫好

    把指令用法、資料夾規格、平台限制、踩過的坑寫成一份 AGENTS.md 或 CLAUDE.md，放在工具資料夾裡。

    這份文件才是真正讓它「自動」的東西。沒有它，你每次都要重講一遍。

THE CONTRACT

Agent 只要產出這個資料夾

這是 AI 跟發布工具之間的介面。檔名和結構對了，剩下的完全不用管。

某個主題/ ├─ xxx-01.jpg 圖片，檔名結尾一定要有編號 ├─ xxx-02.jpg 1080 × 1350，JPEG，兩邊都通吃 ├─ xxx-03.jpg ├─ threads-copy.txt Threads 文案，不放 hashtag └─ instagram-caption.txt IG 文案，要放 hashtag

兩份文案不能共用

語感不一樣

Threads 偏口語短促、不放標籤；IG 資訊量可以多一點，標籤放最後一行。

自動忽略

雜檔不用清

預覽圖、插圖草稿、.DS_Store 這些會被自動跳過，只挑帶編號的素材。

差異

同一組素材，兩套規則

用 1080 × 1350 的 JPEG，兩邊都安全，不用做兩份圖。

實際踩過的坑

這五個會讓你卡住

全部都是這次設定過程中真的撞到的，不是理論上可能發生。

1

權限順序錯了，token 要重產

token 會把當下的權限烙進去。先補發文權限，再產 token。反過來的話，token 拿到也發不出去，整段重來。

2

Tester 邀請要去 Instagram 那邊接受

在 App 後台加完 Instagram Tester 只做了一半。還要登入 instagram.com 接受邀請，否則授權會被擋，而錯誤訊息完全看不出原因。

3

圖還沒處理完就送出，直接 400

發輪播時平台需要時間把每張圖抓下來。要等每一張的狀態變成 FINISHED 再組合，否則回一個沒有說明的 400。圖越多越容易踩到。

4

Topic 標籤發出去就改不了

Threads 沒有編輯 topic 的方法。一律用繁體中文，發之前確認。IG 的文案倒是可以在 App 裡手動改。

5

圖床是 public，別放還沒公開的東西

圖片一上傳就是公開可見。只放確定要發出去的素材。用內容雜湊當檔名，同一張重傳不會產生重複檔。

額外收穫

順手解掉的圖卡問題

為什麼字總是太小

字級是被字數決定的

1080 寬扣掉邊距約 970。主標一行 7 個字最大只能到 138px，斷成兩行 4 字就能到 243px。同一句話，斷行就大一倍。

生圖模型的極限

Logo 和中文字別交給它

模型畫不出真正的品牌 Logo，繁中筆畫也常出錯。讓它只生背景和插圖，Logo 用程式疊上去，字級才會每張都一致。

設定完之後

日常就只剩三步

從素材到兩個平台上線，大約一分鐘。

# 1. 把真的 Logo 蓋上去，順便產縮圖檢查表
$ python3 brand_slides.py ./資料夾

# 2. 先預覽，確認圖和文案都對
$ python3 post_both.py ./資料夾/branded --dry-run

# 3. 兩個平台一起發
$ python3 post_both.py ./資料夾/branded
